# Source Dataset — RavenStack Synthetic SaaS

**Author:** River @ Rivalytics  
**Original source:** [SaaS Subscription & Churn Analytics Dataset on Kaggle](https://www.kaggle.com/datasets/rivalytics/saas-subscription-and-churn-analytics-dataset)  
**Data type:** Fully synthetic, multi-table SaaS activity data

The five CSV files in [`raw/`](raw/) are the original RavenStack source tables used in this project. They are retained unchanged for reproducibility. The publisher requests attribution for educational and portfolio reuse; the source documentation uses the description *“MIT-like”*. Refer to the original Kaggle page for terms and updates.

| File | Rows | Primary role |
| --- | ---: | --- |
| `ravenstack_accounts.csv` | 500 | Account attributes and historical churn flag |
| `ravenstack_subscriptions.csv` | 5,000 | Subscription and plan-change history |
| `ravenstack_feature_usage.csv` | 25,000 | Product usage by subscription |
| `ravenstack_support_tickets.csv` | 2,000 | Support requests and satisfaction |
| `ravenstack_churn_events.csv` | 600 | Recorded churn-related events |

## Relational joins

- `subscriptions.account_id` → `accounts.account_id`
- `feature_usage.subscription_id` → `subscriptions.subscription_id`
- `support_tickets.account_id` → `accounts.account_id`
- `churn_events.account_id` → `accounts.account_id`

**Important:** A source `feature_usage.usage_id` value can appear more than once. Do not deduplicate rows merely because their usage IDs repeat. The SQL Server workflow adds `FEUS_ID` as a surrogate identity key without dropping the underlying records.

The project uses the account `churn_flag` as an **ever-churned** indicator. It is not a current-status field and does not represent monthly churn. The source data also contains temporal inconsistencies assessed by the SQL audit.

## Reproduction

Import the five CSVs individually into SQL Server's `raw` schema after running `sql/00_database_setup.sql`. Then follow [SQL setup](../docs/SQL_SETUP.md) to build the account-level analytical view. The processed CSV under `data/processed/` is generated by the Python notebook and is not included in version control.
